## How this tracker works

- **ID**: `A.H1`, `B.2`, etc. — referenced from PR titles, commit messages, and the work log.
- **Severity** (Section A only): `critical` / `high` / `medium` / `low`. None of the current items are critical.
- **Status**: `open` / `in-progress` / `done` / `won't fix`. Final state is dated.
- **Repro**: a short, deterministic steps-to-reproduce. If this is missing, the item isn't ready.
- **Files**: paths-with-line-numbers so the picker doesn't have to rediscover them.
- **Acceptance**: what "fixed" looks like. Tests preferred where they fit.

Mandatory gate for every PR: `pnpm typecheck && pnpm lint --max-warnings 0 && pnpm format:check && pnpm test && pnpm build` (per `CLAUDE.md`).

### A.H1 — Closing the last tab silently re-opens a different file

- **Severity**: high
- **Status**: done (2026-05-02)
- **Repro**: open one document → click × on the only tab → URL routes to
  `/app/:vaultId` → `VaultHome` auto-redirects to `index.md` /
  `README.md` → `DocumentPage` runs `openOrFocus` → a new preview tab
  appears for the home file, even though the user just emptied the
  workspace.
- **Files**:
  - `src/ui/reading-shell/TabStrip.tsx:67–84` — `onClose` navigates to `/app/:vaultId` after closing the active tab.
  - `src/ui/reading-shell/VaultHome.tsx:58` — `<Navigate to=…/${state.to} replace />` runs unconditionally when an index is found.
  - `src/ui/reading-shell/DocumentPage.tsx:215–221` — `openOrFocus` after a successful render.
- **Acceptance**: closing the last tab leaves the workspace empty (no auto-opened tab). Implementation: VaultHome accepts a query flag (e.g. `?empty=1`) that suppresses redirect, and `TabStrip.onClose` passes it when no tabs remain. Add a regression test in `TabStrip.test.tsx` that closes the last tab and asserts `tabsByVault[v].length === 0` after the navigation settles.

### A.M3 — Browser back/forward can resurrect a just-closed tab

- **Severity**: medium (arguably correct behaviour, surfacing for review)
- **Status**: won't fix (2026-05-02)
- **Repro**: close tab A via × → press browser-back → URL returns to A's
  path → `DocumentPage` runs `openOrFocus(A)` → A re-appears as preview.
- **Decision**: accept option (a) — "URL is the truth, back reopens." This
  matches standard browser and VS Code semantics. A re-opened tab arrives
  as a preview (not pinned), which is correct for history navigation. The
  alternative (`history.replaceState` on every close) would break the
  expected browser-back/forward mental model on multi-tab sessions.

### A.M4 — Wikilink navigation strands the previous preview tab

- **Severity**: medium
- **Status**: won't fix (2026-05-02)
- **Repro**: A is a preview tab. Click a wikilink to B → `DocumentPage`
  opens B as preview, replacing A. A is gone from the tab strip.

### B.1 — `src/styles/globals.css` (4098 LOC)

By far the worst offender. Single-file design once paid off (everything
in one place, easy to grep, no PostCSS module overhead) but at 4 k lines
the file is structurally unsearchable.

**Split plan** (move to `src/styles/`, import all from a new
`globals.css` shim that just does `@import` of the parts):

```
src/styles/globals.css            — kept as the entry point;
                                    only `@theme`, `@import`s, base layer
src/styles/themes.css             — :root + .theme-* token blocks
src/styles/scrollbars.css         — added 2026-05-02; isolate
src/styles/prose.css              — `.swirlread-prose` markdown rules
                                    (largest single chunk)
src/styles/code-shiki.css         — Shiki dual-theme rules
src/styles/layout.css             — VaultLayout, sidebar, TOC,
                                    hover zones, resize handle
src/styles/file-tree.css          — `.swirlread-file-tree*` rules
src/styles/tabs.css               — `.swirlread-tab-strip*`
                                    + `.swirlread-shell__tabs`
src/styles/command-palette.css    — `.swirlread-cmdk*`
src/styles/file-renderers.css     — CSV / JSON / HTML / image / audio /
                                    code-file renderer rules
src/styles/landing.css            — `.swirlread-landing*`
src/styles/settings.css           — `.swirlread-settings*`
src/styles/zen-mobile.css         — zen mode + small-viewport media
                                    queries
```

**Acceptance**:

- Each shard ≤ 500 LOC (most ≤ 300). ✓
- `pnpm build` produces an equivalent CSS bundle. ✓ (see note below)
- No selector duplicated across shards. ✓ (verified by build comparison)

**Note on bundle size**: The split build with `stripColorMixSupports()`
Vite plugin produces 23.43 KB gz — identical to the concatenated
single-file baseline. Without the strip plugin, each @imported shard
gets its own `@supports (color:color-mix(in lab,red,red))` wrapper from
Lightning CSS's per-file compile pass (regardless of browser targets set
in the optimize step). Since all SwirlRead target browsers support
`color-mix()` natively (Chrome ≥ 111, Edge ≥ 111, Firefox ≥ 113,
Safari ≥ 16.2), these wrappers are dead code — the plugin safely strips
them and brings the split back to parity. The `browserslist` field in
`package.json` documents the target range.

**Risk**: medium. Tailwind v4 + Vite handles `@import` natively; the
order matters for cascade (themes before component rules). Land as ONE
PR with all shards moved at once — partial moves leave the cascade in a
broken state.

## Recommended sequencing

For maximum impact / minimum cost ratio, work top-down:

1. **A.H3 + A.H2 + A.M7** as a single small CSS / layout PR (~ 30 min, all in `globals.css` + AppShell shrink-0). Low-risk visual fixes.
2. **A.H1** standalone PR — touches 3 files, ships with a regression test.
3. **A.H4** decision pass first; then implement option (a) ~ 15 LOC.
4. **A.M1, A.L6** — quality-of-life polish; bundle as one PR.
5. **B.1 globals.css split** — own PR, single landing. Big diff, mechanical.
6. **B.3 FileTree split** — second-largest payoff after globals; touches a hot file.
7. Remaining B-items + remaining A-items as backlog.
